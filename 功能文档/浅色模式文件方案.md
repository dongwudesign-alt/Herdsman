### 二、实施策略

**策略 A：独立 CSS 覆盖（推荐）**

每个 `-white.html` 文件复制自源文件，但做以下修改：

* 在 `<style>` 顶部添加 `:root` 变量覆盖块，将上一轮方案中的所有颜色值替换为浅色模式值
* 所有 `href` 链接（侧边栏、导航项）自动指向对应的 `-white.html` 文件
* `window.location.href` 跳转也改为 `-white.html`
* 其余 HTML 结构、JS 逻辑、图片资源路径完全不变

**优点**：修改点集中，错误率低，每页只需改 2 个区域（CSS 变量 + 链接）

**策略 B：内联替换（对于无 CSS 变量的页面）**

对于 `meeting-home`、`meeting-recoding`、`meeting-summary`、`meeting-summary2`、`knowledge`、`image-gen` 等没有使用 `:root` 变量的页面，需要将所有硬编码的颜色值逐一替换为浅色等价色值。

### 四、需要处理的页面分类

**第一类（有 `:root` 变量，修改成本低，约 6 页）：**

* `index.html`、`route.html`、`Routing policy.html`、`Routing configuration.html`、`dashboard.html`、`setting.html`

这些页面已将颜色值抽取到 `:root` 中的 CSS 变量，只需在 `-white.html` 中覆盖变量即可完成 80% 的配色转换，剩余 20% 是硬编码的渐变和阴影。

**第二类（无 `:root` 变量，需要逐项替换，约 8 页）：**

* `image-gen.html`、`model-store.html`、`model-management.html`、`knowledge.html`
* `meeting-home.html`、`meeting-recoding.html`、`meeting-summary.html`、`meeting-summary2.html`

这些页面颜色值分散在 `<style>` 各处，需要逐段替换，其中 `model-management.html` 和 `knowledge.html` 代码量较大。

## 浅色模式 UI 设计方案

### 一、设计原则

* **保持建筑感**：保留现有的毛玻璃（glassmorphism）层次结构，但将玻璃质感从"暗色半透明"转为"亮色半透明"
* **对比度策略**：采用"浅暖底 + 白卡片"的层次，利用微妙的阴影而非深色背景来区分层级
* **饱和度控制**：整体低饱和度（\<10%），仅在可交互元素（toggle、active 态）保留微量蓝色调
* **色温选择**：偏暖灰（#f5f3f0 级别），避免纯白 #fff 带来的刺眼感

### 六、特殊元素调整

**agent-card 已连接态：**

* 深色：渐变 rgba(255,255,255,0.10→0.05) + 白色上边框高光
* 浅色：改为渐变 rgba(0,0,0,0.03→0.01) + 浅色上边框，取消白色高光

**conic-gradient 边框（app-window::before）：**

* 深色：白灰色圆锥渐变
* 浅色：改为灰黑色圆锥渐变，透明度降低 50%，保持质感但不抢眼

**卡片假边框（::before radial-gradient）：**

* 深色：rgba(180,180,195,0.5) → transparent
* 浅色：rgba(0,0,0,0.08) → transparent

**卡片底部光晕（::after）：**

* 深色：rgba(120,120,135,0.18) → transparent
* 浅色：rgba(0,0,0,0.04) → transparent
